# Plotting Style (matplotlib)
Use this house style when reviewing or suggesting plotting code.
- **Style sheet:** Apply `styles/tufte.mplstyle` before plotting (from a `book/<chapter>/`
  notebook: `plt.style.use("../../styles/tufte.mplstyle")`). The original is in
  `UsingPsi4/styles/`; UsingPsi4v2 does not have a `styles/` folder yet.
- **Object-oriented API only:** Create figures with `plt.subplots` and draw on the axes
  (`ax.plot`, `ax.set_xlabel`, ...), never `plt.plot` state-machine style. Start with
  `fig, ax = plt.subplots(nrows=1, ncols=1, figsize=(5,4))`; for several panels, e.g.
  `fig, axs = plt.subplots(nrows=1, ncols=2, figsize=(9,4))`.
- **Lines:** Thin, `linewidth=0.5` or `0.7`.
- **Default markers:** Open circles — `marker="o"`, `markerfacecolor="white"`,
  `markeredgecolor="black"`, `markeredgewidth=0.5`.
- **Additional data series:** Circles with thin outlines (`markeredgewidth=0.5`) filled
  with pastel colours, e.g. `["#AEC6CF", "#FFB3BA", "#BAFFC9", "#FFDFBA", "#CBAACB", "#FFFFBA"]`.
- **Fits behind data:** Draw fit/trend lines under the points with `zorder`
  (fit `zorder=1`, points `zorder=2`).
- **Example:**
  ```python
  fig, ax = plt.subplots(nrows=1, ncols=1, figsize=(5,4))
  ax.plot(x_fit, y_fit, color="black", linewidth=0.7, zorder=1)
  ax.plot(x, y, linestyle="none", marker="o", markerfacecolor="white",
          markeredgecolor="black", markeredgewidth=0.5, zorder=2)
  ax.set_xlabel("x")
  ax.set_ylabel("y")
  ```

# Review Procedures
These are read-only checks. They produce a report; they never change files.

## Compare a rewritten page to the original
When Barry names a page in UsingPsi4v2 (e.g. "compare `book/02-SmallMolecules/021-SmallMolecules.ipynb`"):
1. **Find the source.** Locate the matching page in UsingPsi4 (same chapter number/name;
   check the `toc` in `UsingPsi4/myst.yml` if unsure). Ask if the match is unclear.
2. **Content.** Walk both pages section by section. List what was dropped, added, moved,
   or reworded in a way that changes meaning. Don't comment on wording changes that keep the meaning.
3. **Paths and assets.** Check every figure, image, include, and link path resolves from the
   new page's location in UsingPsi4v2. Flag assets that exist only in UsingPsi4 and still
   need copying over (e.g. `images/`, `styles/`).
4. **Cross-references and citations.** Check `{ref}`/`{numref}` targets and labels exist in
   UsingPsi4v2, and every `{cite}` key is in UsingPsi4v2's `references.bib`.
5. **TOC.** Check the page is listed in UsingPsi4v2's `myst.yml` `toc`, and note any TOC
   entries pointing to files that don't exist yet.
6. **Report.** Group findings as: Missing content · Broken paths/assets · References &
   citations · TOC. Give the source file and section for each item so Barry can find it.
   Put the most important issues first.

## Check Psi4 code
When Barry asks to check the Psi4 input on a page:
1. **Collect the code.** Gather every Psi4 input block and Python cell that calls `psi4`
   (`psi4.geometry`, `set_options`, `energy`, `optimize`, `frequency`, `variable`, etc.).
2. **Check against the 1.11.x manual** (`psi4docs/sphinxman/1.11.x`, reST in `_sources/`):
   - Option names and allowed values (e.g. `reference`, `scf_type`, `basis`, `opt_type`,
     `g_convergence`, PCM/solvent options).
   - Method and basis set names are spelled as Psi4 expects and are available.
   - PSI variable names read with `psi4.variable()` exist.
   - Function calls and keyword arguments (`return_wfn`, `molecule=`, etc.) match the API.
   - Geometry blocks: charge/multiplicity line, units, Z-matrix variables defined,
     `symmetry`/`no_reorient`/`no_com` used correctly.
   - Geometry optimizer options against the optking docs/source where needed.
3. **Resources.** Flag runs that exceed the house limits of 4 threads and 4 GB memory, or
   that don't set them.
4. **Methods.** Note when a method choice departs from the house defaults (HF and similar
   low-cost methods first; DFT such as B3LYP or CCSD(T) for single points) without a reason
   given in the text.
5. **Report.** For each issue give the cell/line, what's wrong, the fix, and the manual
   page that supports it. Say clearly when something can't be confirmed in the manual.
   Do not run calculations unless Barry asks.
